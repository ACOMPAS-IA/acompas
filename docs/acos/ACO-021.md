# ACO-021 — Integración de Presidio con MEDDOCAN

## 1. Identificación

- **ID:** ACO-021
- **Nombre:** Integración de Presidio con MEDDOCAN
- **Responsable:** Miguel Martínez
- **Soporte / revisión:** Luis del Olmo
- **Estimación:** 10–12 h
- **Dependencia:** ACO-020

## 2. Objetivo

Integrar Presidio Analyzer con el modelo MEDDOCAN para disponer de un motor de detección de entidades clínicas en español que pueda ser utilizado posteriormente por el servicio de anonimización de ACOMPAS.

El objetivo de este ACO es disponer del motor de detección. La política completa de anonimización se implementará en ACO posteriores.

## 3. Incluye

1. Incorporar las dependencias necesarias para utilizar Presidio Analyzer y el motor NLP requerido.
2. Integrar el modelo `BSC-NLP4BIA/bsc-bio-ehr-es-meddocan`.
3. Configurar Presidio para trabajar con idioma español.
4. Configurar `TransformersNlpEngine`.
5. Definir explícitamente el mapeo entre categorías MEDDOCAN y tipos de entidad de Presidio/ACOMPAS.
6. Construir un `AnalyzerEngine` funcional.
7. Exponer una función de construcción del analyzer reutilizable por componentes posteriores.
8. Comprobar que el analyzer procesa texto clínico sintético en español.
9. Añadir las pruebas mínimas necesarias para comprobar construcción y detección.

## 4. Resultado esperado

Debe existir un `AnalyzerEngine` configurado para español que:

- utilice MEDDOCAN como modelo NER;
- pueda analizar texto clínico sintético;
- devuelva detecciones de entidades;
- pueda ser utilizado posteriormente por el servicio de anonimización.

El resultado de este ACO es **detección**, no anonimización completa.

## 5. Fuera de alcance

No forman parte de ACO-021:

- creación de reconocedores personalizados;
- reglas específicas de DNI;
- reglas específicas de historia clínica;
- filtros de falsos positivos;
- allow-list;
- política definitiva de qué entidades se anonimizan;
- umbral de confianza de negocio;
- transformación/anonymización del texto;
- API HTTP;
- persistencia;
- frontend;
- autenticación;
- tests E2E.

Estas funciones corresponden a ACO posteriores u otras áreas del proyecto.

## 6. Dependencias

ACO-021 depende de **ACO-020 — Servicio de anonimización**.

Debe respetar el contrato y la estructura establecidos por ACO-020 y no modificar su responsabilidad.

## 7. Restricciones técnicas

### Modelo

`BSC-NLP4BIA/bsc-bio-ehr-es-meddocan`

### Idioma

`es`

### Motor

Presidio Analyzer + `TransformersNlpEngine`.

### NLP auxiliar

La configuración debe utilizar el modelo spaCy requerido por `TransformersNlpEngine` para tokenización/procesamiento auxiliar, sin convertirlo en el motor NER principal de este ACO.

## 8. Mapeo de entidades

El modelo MEDDOCAN proporciona categorías que deben mapearse a tipos de entidad utilizados por Presidio/ACOMPAS.

El mapeo debe quedar explícito y ser revisable.

Las categorías detectables pero excluidas de la lista de entidades objetivo de anonimización deben mantenerse diferenciadas de las entidades que posteriormente se anonimicen.

La política definitiva de anonimización no se decide en este ACO.

## 9. Umbral

ACO-021 no establece la política definitiva de umbral de confianza.

El analyzer debe conservar/devolver la puntuación disponible en Presidio para permitir que ACO-023 establezca posteriormente la política de filtrado y confianza.

No incorporar en este ACO una política de negocio de anonimización basada en umbral.

## 10. Datos de prueba

Está prohibido utilizar documentos reales de pacientes.

Las pruebas utilizarán texto clínico sintético en español.

Como mínimo debe existir un caso sintético que permita comprobar detecciones representativas de entidades relevantes.

## 11. Criterios de aceptación

### AC-01 — Construcción

El `AnalyzerEngine` puede construirse correctamente dentro del entorno Docker del proyecto.

### AC-02 — Modelo

El analyzer utiliza MEDDOCAN como modelo NER.

### AC-03 — Español

El analyzer puede analizar texto utilizando el idioma `es`.

### AC-04 — Detección

El analyzer devuelve detecciones sobre texto clínico sintético en español.

### AC-05 — Puntuación

Las detecciones proporcionan la información de confianza disponible en Presidio para su posterior utilización por ACO-023.

### AC-06 — No persistencia

La implementación no introduce persistencia de documentos clínicos originales.

### AC-07 — Sin datos reales

No se incorporan documentos reales de pacientes al código, tests, fixtures, logs o repositorio.

### AC-08 — Tests

Las pruebas asociadas al comportamiento implementado pasan correctamente.

### AC-09 — Alcance

El PR no incorpora funcionalidades pertenecientes a ACO-022, ACO-023, ACO-024 o ACO-025 salvo cambios mínimos imprescindibles para la integración.

## 12. Tests esperados

Como mínimo:

1. Construcción correcta del `AnalyzerEngine`.
2. Análisis de texto sintético en español.
3. Detecciones esperadas en un caso sintético conocido.
4. Disponibilidad de puntuaciones de confianza.
5. Ausencia de dependencia de documentos reales.

Los tests no deben depender de servicios externos no documentados.

## 13. Componentes esperados

La implementación debe limitarse, salvo necesidad justificada, a:

- configuración de dependencias;
- construcción/configuración del analyzer;
- tests relacionados con el analyzer;
- integración mínima necesaria con la estructura de ACO-020.

Si se modifican otros componentes, el PR debe explicar por qué.
